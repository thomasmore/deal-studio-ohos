3D WORLD APPS
This request is solid things in 3D: bodies that are thrown, fall, stack, roll and knock into each other, or circle a
centre. Build it on one ui.World described with std/scene, not on a ui.Surface and not out of buttons and cards drawn
to look 3D.

Describe the world; never animate it:
- build(state: AppState): scene.Thing[] returns the whole world -- the camera, the table or floor, every body -- and runs
  only when the state changes, never per frame. There is no frame function. The host moves everything: physics moves
  loose bodies, the host turns spins and carries orbits. The program never keeps a position, an angle or a velocity in
  the state to move a body, and never uses a ui.Ticker to animate one.
- Once a loose body exists its x, y, z are only where it started: returning it somewhere else does nothing. To throw it
  again, change its kick trigger (a count in the state, state.throws + 1). To put it back where it started, give it a
  new id: a round number in the id ("r" + ui.numberToString(state.round) + "-" + ...) makes build create it afresh.
- Keep in the state only what the person did and what the world told: counts of throws, shots and rounds, the faces
  last read, a score, the body last tapped. AppState holds no scene.Thing.
- build is cheap: a few loops that push things, nothing computed per body beyond its place and colour. Make rows,
  walls, stacks and rings with loops, never as long literal lists.

The shape of the program:
- view(state) returns ui.AppTheme(preset, "", [ui.Column("default", [ui.Header(...), ui.World("default", 0, "build",
  "onWorld"), ui.Text(...) with the result, ui.Button(...) for what the person does])]). The result -- what the world
  told: the faces, a count, the body tapped -- is a ui.Text under the world, not drawn in it.
- Choose the World's style from the request. "full" when the world is the app, something to watch and explore -- a
  system in motion, a simulation, a scene to turn round, or whenever full screen or immersive is asked for: it opens over
  the whole screen with the Header's title small in its corner and the text of the ui.Text after it as a caption over
  its bottom -- no buttons: those are on the normal screen, a tap on the corner button away. So the main thing of a
  full world is done by touching the world (a tap on a body names it, a drag turns the view, a pinch zooms; the words on screen call the bodies what they are in this
  scene, never "body"), its result is one short
  ui.Text("body", ...) line, and Buttons are extras (speed, reset). Keep the Header all the same: it names the app,
  and is shown in full on the normal screen. "fill" for something played with the controls under it: the world takes
  the screen between the Header and them. "default" for a small world among other content.
  Every world has a corner button that opens it full screen and back, so the person can always choose.
- onWorld(state: AppState, e: scene.Event): AppState hears the world: e.kind is "tap" (a finger on e.body, "" for empty
  space), "swipe" (a flick of e.body; e.x, e.z its direction along the floor, e.speed how fast), "hit" (knocks, told at most
  four times a second: e.bodies every body knocked since the last hit, e.values how hard each was knocked in m/s, e.body
  knocked into e.other the hardest of them at e.speed; count e.bodies.length() or keep the hardest, nothing more) or
  "settled" (every loose body at rest after a throw; e.bodies the ids, e.values the face each die shows, and for a body
  that is not a die 1 when it was knocked from where it was built -- moved or tipped over -- and 0 when it still
  stands). Nothing else is told: not where a body is, not whether it left the table. Score from these (hits, faces,
  blocks knocked over), and count a settled body once, from that event, not from hits. Return the state unchanged for
  the kinds it does not use: then nothing is built or drawn again.
- A Button does the main thing too (the throw, putting things back), so the app works without knowing where to tap.

Scale, units and placement:
- Units are metres and y is up; the floor or the table top is y = 0. Size the scene for the phone, not for reality:
  each body the person watches or plays with is a good part of the view, so small real things are made several times
  bigger and huge ones smaller, keeping their proportions to each other. A table or floor is just big enough for what
  is on it and what is thrown across it, and the scene is 0.3 to 5 m across. Things that are huge and far apart
  in reality (a centre and what circles it) are not to scale: the widest orbit at most about 4.5 (the camera steps back
  until all of it fits the narrow screen), the centre about a tenth of that in radius, every body circling it at least
  a fiftieth of it in radius so it still shows, periods of a few seconds to a minute.
- Show every body the request implies, as many as the real thing has, and never leave one out to save room: make the
  bodies smaller instead.
- Bodies circling one centre pass each other, so lay orbits out from the inside: each orbit is further from the one
  inside it than the two bodies reach added together, plus 0.05 -- a body reaches its radius, its rings' outer edge,
  or the orbit of what circles it plus that body. A small body can sit close to its neighbours; a big or ringed one
  needs room.
- A body of height h stands on the ground at y = h / 2. Bodies never start inside one another or under y = 0. Bodies
  meant to stand together touch: a row of side s is s apart, a stack s higher each level. Bodies meant to be told
  apart -- thrown, picked, counted -- start about 1.5 times their size apart, so they read as separate things. Loose
  bodies start over the table or floor, near x = 0, z = 0; with a table, inside its width and depth.
- A body has the shape of the thing it is. A box, ball or cylinder only for a thing of that shape; any other flat
  shape (a triangle, a star, an arrow, a piece of a game) is scene.shape with its corners in order round it -- a flat
  sheet; scene.thick only for a thing that has a thickness (a tile, a coin, a slab), never for one asked for flat or
  thin -- and a solid one with points and flat faces (a pyramid, a crystal, a wedge) is scene.hull. Never stand a
  box in for a shape the request names. A thing of several parts (an animal, a vehicle, a snowman, furniture) is one scene.group of its
  parts, each placed from the group's centre; wrap the group, never a part, so it falls and is thrown as one body.
- Every body has an id of its own (ids built with ui.numberToString in loops), at most 300 bodies; about 100 loose
  bodies is plenty.
- The host adds nothing to the scene by itself. Behind the world is the app's background unless scene.sky gives a
  colour and how many stars (a night sky, deep space); an orbit's path is drawn only with scene.trail; a glowing body
  that stands still lights the bodies round it from where it is (a sun, a lamp). There are no other lines, rings or
  outlines in 3D: never build stars, a backdrop or a path from bodies (a cylinder is a solid disc).
- Colours: theme roles (accent, warning, danger, surface, ink ...) or "#rrggbb". A real thing has its real colours;
  bodies the person should tell apart differ in colour.

The camera: scene.camera(x, y, z, lookX, lookY, lookZ, orbit) stands back from the bodies and above them, looking at
their middle: for a scene about s metres across, about 2 s away and 1 to 1.5 s up; for bodies circling a centre, high
above the centre and a little back from it, so the orbits use the tall screen. orbit true lets a drag on empty space
turn the view and a pinch bring it nearer, both done by the host, for a scene to look round; false when the view is
part of the play (a table seen from where the player sits). Frame the whole world: the person pinches in to see small
things.
Leave the camera out and the host frames everything.

What a world can do, combined as the request needs:
- Throwing: scene.kick(scene.loose(body, mass), trigger, vx, vy, vz, spin) throws the body each time trigger changes: a
  count in the state that a Button, a tap or a swipe adds 1 to. A throw goes a few metres a second up and under one
  across; alternate its direction with each throw so the bodies stay on the table or near the middle. While the count
  is ahead of the throw last read, the result is still to come: say so.
- Reading the result: "settled" comes once every thrown body is at rest. e.values say what each did -- a die the face
  on top, any other body 1 when it was knocked from where it was built -- in the order of e.bodies. Keep the result in
  the state (and the throw it belongs to) and show it; leave out the bodies that did the knocking.
- Putting things back: a round number in every id ("r" + ui.numberToString(state.round) + "-" + ...), and a Button adds
  1 to it: every body is made afresh where it is written. A fresh body for each shot the same way, a count in its id.
- More bodies: a count in the state that a Button adds 1 to; a loose body made in the air falls when it is created.
- Circling: no floor or table (nothing falls), a scene.sky if the scene is set in the sky or in space, scene.trail on
  the bodies whose paths should show, the centre body scene.glow if it shines, each body circling
  it scene.orbit(scene.spin(..., dayS), centreId, radius, periodS, phaseDeg), and what circles a circling body orbiting
  that body. Make every body look like what it is with scene.paint: choose the pattern by the kind of surface it has
  and give its colours. A real body has its real colours, surface, rings, tilt and relative periods as you know them,
  whatever palette the design names; invented ones are for made-up worlds. Spin each body once every few seconds so
  its surface is seen turning, a tilt with scene.turn(thing, 0, 0, degrees) inside the spin:
  spin(turn(paint(sphere(...), pattern, colour2), 0, 0, tilt), dayS). Wrap the body the person tapped
  (state.selected === its id) in scene.mark(thing, "accent") -- never recolour it, its colours say what it is -- and
  the Text says its name and facts.
- One thing to look at: the body or bodies it is made of, standing still or turning with scene.spin, an orbiting camera,
  and Buttons for what the person may change in it.

A complete example of these parts in one program, with no game in it. Write your own program for the request; take the
structure and the calls from this, not its bodies.

--- EXAMPLE ---
// The parts of a world, with no game in them: the example the world guide carries (vera-world-skill.txt).
//
// Three loose bodies stand on a floor, made in a loop. Throw (the button, or a flick of a body) adds 1 to state.throws,
// the kick trigger of each, so the physics throws them again from where they lie, each time the other way. When all
// have come to rest the world sends "settled" and the program reads it. Reset adds 1 to state.round, which is in every
// id, so the bodies are made afresh where they were written. A tap names a body and marks it. The program never moves
// a body itself.

@jsonable
class AppState {
  throws: number;
  read: number;
  round: number;
  moved: number;
  picked: string;
}

function init(): AppState {
  return {throws: 0, read: 0, round: 0, moved: 0, picked: ""};
}

function build(state: AppState): scene.Thing[] {
  let things: scene.Thing[] = [];
  things.push(scene.camera(0, 0.9, 1.4, 0, 0.05, 0, true));
  things.push(scene.floor("surface"));
  // Each throw goes the other way, so the bodies stay near the middle however often they are thrown.
  let way: number = 1;
  if (state.throws % 2 === 1) {
    way = -1;
  }
  let colours: string[] = ["accent", "warning", "#22c55e"];
  let i: number = 0;
  while (i < 3) {
    let id: string = "r" + ui.numberToString(state.round) + "-" + ui.numberToString(i);
    let x: number = (i - 1) * 0.3;
    let body: scene.Thing = scene.box(id, x, 0.05, 0, 0.1, 0.1, 0.1, colours[i]);
    if (i === 1) {
      body = scene.cylinder(id, x, 0.06, 0, 0.05, 0.12, colours[i]);
    } else if (i === 2) {
      body = scene.sphere(id, x, 0.05, 0, 0.05, colours[i]);
    }
    if (state.picked === id) {
      body = scene.mark(body, "accent");
    }
    things.push(scene.kick(scene.loose(body, 1), state.throws, 0.3 * way, 2, 0.2 * way, 1));
    i = i + 1;
  }
  return things;
}

function onThrow(state: AppState, value: number): AppState {
  return {throws: state.throws + 1, read: state.read, round: state.round, moved: state.moved, picked: state.picked};
}

function onReset(state: AppState, value: number): AppState {
  return {throws: state.throws, read: state.throws, round: state.round + 1, moved: 0, picked: ""};
}

function onWorld(state: AppState, e: scene.Event): AppState {
  if (e.kind === "swipe") {
    return onThrow(state, 0);
  }
  if (e.kind === "tap") {
    return {throws: state.throws, read: state.read, round: state.round, moved: state.moved, picked: e.body};
  }
  if (e.kind !== "settled") {
    return state;
  }
  // For a body that is not a die, e.values says 1 when it was knocked from where it was built.
  let moved: number = 0;
  for (let v: number of e.values) {
    moved = moved + v;
  }
  return {throws: state.throws, read: state.throws, round: state.round, moved: moved, picked: state.picked};
}

function view(state: AppState): ui.View {
  let result: string = "Throw them, or tap one";
  if (state.throws > state.read) {
    result = "In the air...";
  } else if (state.throws > 0) {
    result = ui.numberToString(state.moved) + " of 3 moved";
  }
  if (state.picked !== "") {
    result = result + " - picked " + state.picked;
  }
  return ui.AppTheme("clean", "", [
    ui.Column("default", [
      ui.Header("default", "Bodies", "", "Flick one or press Throw", ""),
      ui.World("fill", 0, "build", "onWorld"),
      ui.Text("body", result),
      ui.ActionBar("spread", [
        ui.Button("primary", "Throw", "onThrow", 0, true),
        ui.Button("secondary", "Reset", "onReset", 0, state.round >= 0)
      ])
    ])
  ]);
}
