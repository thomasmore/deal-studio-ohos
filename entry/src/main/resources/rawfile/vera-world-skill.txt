3D WORLD APPS
This request is solid things in 3D: bodies that are thrown, fall, stack, roll and knock into each other, circle a
centre, walk or drive about by themselves, or are steered by the person. Build it on one ui.World described with std/scene, not on a ui.Surface and not out of buttons and cards drawn
to look 3D.

Describe the world; never animate it:
- build(state: AppState): scene.Thing[] returns the whole world -- the camera, the table or floor, every body -- and runs
  only when the state changes, never per frame. There is no frame function. The host moves everything: physics moves
  loose bodies, the host turns spins, carries orbits, walks bodies along their routes and steers the player by the
  stick it draws. The program never keeps a position, an angle or a velocity in the state to move a body, and never
  uses a ui.Ticker to animate one: moving is a wrapper on the body (scene.path, scene.wander, scene.player ...).
- Once a loose body exists its x, y, z are only where it started: returning it somewhere else does nothing. To throw it
  again, change its kick trigger (a count in the state, state.throws + 1). To put it back where it started, give it a
  new id: a round number in the id ("r" + ui.numberToString(state.round) + "-" + ...) makes build create it afresh.
- Keep in the state only what the person did and what the world told: counts of throws, shots and rounds, the faces
  last read, a score, the body last tapped. AppState holds no scene.Thing.
- build is cheap: a few loops that push things, nothing computed per body beyond its place and colour. Make rows,
  walls, stacks and rings with loops, never as long literal lists.

The shape of the program:
- view(state) returns ui.AppTheme(preset, "", [ui.Column("default", [ui.Header(...), ui.World("default", 0, "build",
  "onWorld"), ui.Text(...) with the result, ui.Button(...) for what the person does])]). The result -- what the world
  told: the faces, a count, the body tapped -- is a ui.Text under the world, not drawn in it.
- Choose the World's style from the request. "full" when the world is the app, something to watch and explore -- a
  system in motion, a simulation, a scene to turn round, or whenever full screen or immersive is asked for: it opens over
  the whole screen with the Header's title small in its corner and the text of the ui.Text after it as a caption over
  its bottom -- no buttons: those are on the normal screen, a tap on the corner button away. So the main thing of a
  full world is done by touching the world (a tap on a body names it, a drag turns the view, a pinch zooms; the words on screen call the bodies what they are in this
  scene, never "body"), its result is one short
  ui.Text("body", ...) line, and Buttons are extras (speed, reset). Keep the Header all the same: it names the app,
  and is shown in full on the normal screen. "fill" for something played with the controls under it: the world takes
  the screen between the Header and them. "default" for a small world among other content.
  Every world has a corner button that opens it full screen and back, so the person can always choose.
- onWorld(state: AppState, e: scene.Event): AppState hears the world: e.kind is "tap" (a finger on e.body, "" for empty
  space; e.x, e.y, e.z is always a point -- where the finger met the body, or 40 m along the ray on empty space -- and
  e.dx, e.dy, e.dz the direction of the ray from the eye through the finger), "swipe" (a flick of e.body; e.x, e.z its
  direction along the floor, e.speed how fast), "hit" (knocks, told at most
  four times a second: e.bodies every body knocked since the last hit, e.values how hard each was knocked in m/s, e.body
  knocked into e.other the hardest of them at e.speed; count e.bodies.length() or keep the hardest, nothing more) or
  "settled" (every loose body at rest after a throw; e.bodies the ids, e.values the face each die shows, and for a body
  that is not a die 1 when it was knocked from where it was built -- moved or tipped over -- and 0 when it still
  stands), "enter" (e.body came into the zone e.other), "action" (a button of the player's was pressed: e.other its
  label, e.x, e.y, e.z where the player is and e.dx, e.dy, e.dz the way it faces) or "struck" (a scene.target, or a
  shot, knocked hard: e.body the one struck, e.other what struck it, "" for the ground, e.speed how hard in m/s -- its
  strength -- and e.bodies with e.values every one struck since the last struck and how hard). Nothing else is told: not
  where a body is apart from these, not whether it left the table. Score from these (hits, faces, blocks knocked over,
  strikes), and count a settled body once, from that event, not from hits. Return the state unchanged for
  the kinds it does not use: then nothing is built or drawn again.
- A Button does the main thing too (the throw, putting things back), so the app works without knowing where to tap.
  A world with a player is played with the stick: its Buttons are extras (faster, start again).

Scale, units and placement:
- Units are metres and y is up; the floor or the table top is y = 0. Size the scene for the phone, not for reality:
  each body the person watches or plays with is a good part of the view, so small real things are made several times
  bigger and huge ones smaller, keeping their proportions to each other. A table or floor is just big enough for what
  is on it and what is thrown across it, and the scene is 0.3 to 5 m across. Things that are huge and far apart
  in reality (a centre and what circles it) are not to scale: the widest orbit at most about 4.5 (the camera steps back
  until all of it fits the narrow screen), the centre about a tenth of that in radius, every body circling it at least
  a fiftieth of it in radius so it still shows, periods of a few seconds to a minute.
- Show every body the request implies, as many as the real thing has, and never leave one out to save room: make the
  bodies smaller instead.
- Bodies circling one centre pass each other, so lay orbits out from the inside: each orbit is further from the one
  inside it than the two bodies reach added together, plus 0.05 -- a body reaches its radius, its rings' outer edge,
  or the orbit of what circles it plus that body. A small body can sit close to its neighbours; a big or ringed one
  needs room.
- A primitive body of height h stands on the ground at y = h / 2. A scene.model instead takes y as its SUPPORT BOTTOM:
  y = 0 on the ground or y = the top of a supporting body. Its x/z are the support midpoint; the host places its body
  centre at y plus half its scaled height. Never add half the height yourself. Bodies never start inside one another or under y = 0. Bodies
  meant to stand together touch: a row of side s is s apart, a stack s higher each level. Bodies meant to be told
  apart -- thrown, picked, counted -- start about 1.5 times their size apart, so they read as separate things. Loose
  bodies start over the table or floor, near x = 0, z = 0; with a table, inside its width and depth.
- Prefer a matching imported model from the std/scene model catalogue instead of reconstructing it from primitives.
  scene.model(id, name, x, y, z, size) takes an exact catalogue name and scales uniformly so the longest body side is
  size metres, keeping its own imported colours. It is one ordinary body with a convex collision hull, already facing
  +x; never compensate for the asset's original front with a 90-degree turn. Use primitives when no model matches.
  Models cannot be group parts and cannot use paint, glow or split; these are rejected, not ignored. mark and rings
  may wrap models; ordinary motion wrappers work on them. Use primitive bodies for things that need to break.
  turn rotates about the converted body centre, not its feet, without adjusting height: tilting may require a different
  support bottom to keep the rotated hull grounded. path and wander keep the converted centre height and add their
  heading to turn; leave turn at zero to face the route. orbit ignores the model's placement and uses its centre body's
  centre height. from takes the converted centre offset, including half the scaled model height, in the parent's frame,
  not above the world ground. Imported models have no separately animated parts.
- A body has the shape of the thing it is. A box, ball or cylinder only for a thing of that shape; any other flat
  shape (a triangle, a star, an arrow, a piece of a game) is scene.shape with its corners in order round it -- a flat
  sheet; scene.thick only for a thing that has a thickness (a tile, a coin, a slab), never for one asked for flat or
  thin -- and a solid one with points and flat faces (a pyramid, a crystal, a wedge) is scene.hull. Never stand a
  box in for a shape the request names. Without a matching model, a thing of several parts is one scene.group of its
  parts, each placed from the group's centre; motion, glow and mark wrap the group, so it falls and is thrown as one body.
  Paint and turn may wrap individual parts; swing belongs on a part.
- Every body has an id of its own (ids built with ui.numberToString in loops), at most 300 bodies; about 100 loose
  bodies is plenty.
- The host adds nothing to the scene by itself. Behind the world is the app's background unless scene.sky gives a
  colour and how many stars (a night sky, deep space); an orbit's path is drawn only with scene.trail; a glowing body
  that stands still lights the bodies round it from where it is (a sun, a lamp); a zone is a faint ring on the ground.
  There are no other lines, rings or outlines in 3D: never build stars, a backdrop or a path from bodies (a cylinder is a solid disc).
- Colours: theme roles (accent, warning, danger, surface, ink ...) or "#rrggbb". A real thing has its real colours;
  bodies the person should tell apart differ in colour.
- Materials: scene.paint(thing, pattern, color2) uses the thing's first colour and color2. Material patterns work on
  every primitive body, individual group parts, whole groups, tables and floors; choose by the surface's appearance
  from the catalogue. Sphere-only patterns work only on spheres. Painting a whole group replaces every part's prior
  paint while keeping each part's first colour; paint parts separately for different materials. Patterns repeat in
  metres rather than stretching across faces. Make the painted surfaces large enough in the view to see their pattern;
  a tiny decorative painted part does not make an otherwise unpainted scene read as textured.

The camera: scene.camera(x, y, z, lookX, lookY, lookZ, orbit) stands back from the bodies and above them, looking at
their middle: for a scene about s metres across, about 2 s away and 1 to 1.5 s up; for bodies circling a centre, high
above the centre and a little back from it, so the orbits use the tall screen. orbit true lets a drag on empty space
turn the view and a pinch bring it nearer, both done by the host, for a scene to look round; false when the view is
part of the play (a table seen from where the player sits). Frame the whole world: the person pinches in to see small
things.
Leave the camera out and the host frames everything; in a world with a player it follows the player instead, and
scene.follow(body, distance, height) has it follow any other body that travels.

What a world can do, combined as the request needs:
- Throwing: scene.kick(scene.loose(body, mass), trigger, vx, vy, vz, spin) throws the body each time trigger changes: a
  count in the state that a Button, a tap or a swipe adds 1 to. A throw goes a few metres a second up and under one
  across; alternate its direction with each throw so the bodies stay on the table or near the middle. While the count
  is ahead of the throw last read, the result is still to come: say so.
- Reading the result: "settled" comes once every thrown body is at rest. e.values say what each did -- a die the face
  on top, any other body 1 when it was knocked from where it was built -- in the order of e.bodies. Keep the result in
  the state (and the throw it belongs to) and show it; leave out the bodies that did the knocking.
- Putting things back: a round number in every id ("r" + ui.numberToString(state.round) + "-" + ...), and a Button adds
  1 to it: every body is made afresh where it is written. A fresh body for each shot the same way, a count in its id.
- More bodies: a count in the state that a Button adds 1 to; a loose body made in the air falls when it is created.
- Circling: no floor or table (nothing falls), a scene.sky if the scene is set in the sky or in space, scene.trail on
  the bodies whose paths should show, the centre body scene.glow if it shines, each body circling
  it scene.orbit(scene.spin(..., dayS), centreId, radius, periodS, phaseDeg), and what circles a circling body orbiting
  that body. Make every body look like what it is with scene.paint: choose the pattern by the kind of surface it has
  and give its colours. A real body has its real colours, surface, rings, tilt and relative periods as you know them,
  whatever palette the design names; invented ones are for made-up worlds. Spin each body once every few seconds so
  its surface is seen turning, a tilt with scene.turn(thing, 0, 0, degrees) inside the spin:
  spin(turn(paint(sphere(...), pattern, colour2), 0, 0, tilt), dayS). Wrap the body the person tapped
  (state.selected === its id) in scene.mark(thing, "accent") -- never recolour it, its colours say what it is -- and
  the Text says its name and facts.
- Walking by itself: a thing that walks, runs, drives or roams about is one body -- a matching scene.model or a
  scene.group built facing +x -- in scene.path(body, [x1, z1, x2, z2, ...], speed, true)
  for a route round the scene, its corners clear of what stands there, or scene.wander(body, radius, speed) to roam
  round where it is put. A model takes y = 0 on the ground; a primitive or group has its centre at half its height.
  It faces the way it goes by itself.
  Legs swing as it goes: scene.swing(leg, 20 to 30, 0.6 to 1, phase) on each leg part, the legs of a pair opposite
  (phaseDeg 0 and 180); they stop when it stands. A speed from the state (a Faster button) changes its pace and it
  goes on from where it is. scene.spin only turns a thing where it stands: never use it for a thing that moves about.
- Steered by the person: scene.player(body, speed, action), one per world. The host draws the stick and the camera
  follows the player (a scene.camera is set aside then: leave it out); action names a button beside the stick, "" for none, heard as
  e.kind === "action"; scene.player(body, speed, action, fire) adds a second button, and e.other says which was
  pressed. These buttons are the controls: never repeat them as ui.Buttons under the world. A jump is the player's own kick, its trigger a count the action adds 1 to:
  scene.player(scene.kick(body, state.jumps, 0, 4, 0, 0), speed, "Jump"). The player starts on the floor, clear of
  everything, and does not climb onto bodies: what is in its way is gone round or jumped. Use a floor, not a table
  (it can go 100 m each way), and the World's style "fill" or "full", so the stick has room.
- Places on the ground: scene.zone(id, x, z, r, colour) is a circle a body passes through; "enter" says which body
  came into which zone: a finish, a checkpoint, something to collect (keep the ids collected in the state and leave
  them out of build). Others that go the same way are bodies on paths through the same zones: the order of their
  "enter" events is who came first.
- Shooting: whatever shoots, and whatever it holds (that is only how it looks), what it fires is a shot that flies. A count of shots in the state, which the button or tap that fires adds 1 to. build makes only the last
  few shots (a loop from the count less a few up to the count), each a new id from its number, so a shot once made
  flies on by itself: scene.from(scene.shoot(body, speed, false), shooterId, 0) with the body's x just ahead of the
  shooter's centre along +x (one built inside the shooter is moved ahead of it), so it leaves the way the shooter
  faces, and its y at the height of the middle of what it is meant to hit (a shot that flies straight keeps the height it
  starts at: from the top of a tall shooter it passes over everything low); wrap it in scene.aim(..., x, y, z) to send it at a point instead, the last tap's e.x, e.y, e.z kept in the
  state. A tap that fires sends the shot at the point tapped: keep e.x, e.y, e.z in the state and aim at them. arc true
  for a thing thrown or lobbed, false for one that flies straight. The host keeps only the newest shots (scene.shoot says how many) and drops the oldest.
  What a shot did is known only from "struck" when it lands, never when it is fired: count a hit there.
- Breaking: what can break is a scene.target -- a primitive or group, never an imported model; also a thing that walks or wanders by itself (its pieces
  then fall loose). Only a shot, a thrown or falling body, a blast or the steered one running into it strikes it: a
  part of a body that turns (a limb, or what it holds) strikes nothing. On a "struck" above a strength (e.speed, or e.values for each of
  e.bodies) the handler keeps the id in the state (a list of broken ids), and from then on build returns the pieces of
  scene.split(thing, n, burst) in its place instead of it, so the pieces start where it was and fly apart. Pieces are
  never split again and are not targets.
- A blast: scene.blast(id, trigger, x, y, z, radius, strength) pushes every loose body near the point away each time
  its trigger, a count in the state, changes; when it moves loose bodies other than the player and shots, "settled"
  follows as it follows a throw. The host adds debris and smoke
  at the blast point automatically: do not add a scene.burst for the same effect.
- Particles: scene.burst(id, trigger, x, y, z, kind, color) is a brief visual effect, not a body; it works without
  physics. Choose kind by appearance from the catalogue: sparks, smoke, dust, debris or confetti. Start the trigger at 0:
  its value in the world's first state emits nothing; each change after it, including back to 0, emits once. Editing
  position, kind or colour with the same trigger emits nothing. Keep the trigger count and any event point in state; the host animates and removes particles, never a
  ui.Ticker. Give bursts ids unique among all bodies, zones, blasts and other bursts. Shots striking bodies already
  give sparks at contact, and hard watched knocks give dust; never duplicate these automatic effects with scene.burst.
- In words on the screen call shots and pieces what they are in this scene, never "shot", "piece" or "body", and never
  show an id (e.body, e.other): say what the thing is.
- One thing to look at: the body or bodies it is made of, standing still or turning with scene.spin, an orbiting camera,
  and Buttons for what the person may change in it. A thing asked for as moving, walking or going somewhere is not
  this: it walks by itself.

A complete example of these parts in one program, with no game in it. Write your own program for the request; take the
structure and the calls from this, not its bodies.

--- EXAMPLE ---
// The parts of a world, with no game in them: the example the world guide carries (vera-world-skill.txt).
//
// Three loose bodies stand on a floor, made in a loop. Throw (the button, or a flick of a body) adds 1 to state.throws,
// the kick trigger of each, so the physics throws them again from where they lie, each time the other way. When all
// have come to rest the world sends "settled" and the program reads it. Reset adds 1 to state.round, which is in every
// id, so the bodies are made afresh where they were written. A tap names a body and marks it. The program never moves
// a body itself.

@jsonable
class AppState {
  throws: number;
  read: number;
  round: number;
  moved: number;
  picked: string;
}

function init(): AppState {
  return {throws: 0, read: 0, round: 0, moved: 0, picked: ""};
}

// The id of body i in this round: build makes the bodies with it, and view finds which was picked with it.
function bodyId(round: number, i: number): string {
  return "r" + ui.numberToString(round) + "-" + ui.numberToString(i);
}

// What the picked body is, in words: the name kept beside it, found by its exact id, never read out of the id.
function pickedName(state: AppState): string {
  let names: string[] = ["the cube", "the cylinder", "the ball"];
  let i: number = 0;
  while (i < 3) {
    if (state.picked === bodyId(state.round, i)) {
      return names[i];
    }
    i = i + 1;
  }
  return "";
}

function build(state: AppState): scene.Thing[] {
  let things: scene.Thing[] = [];
  things.push(scene.camera(0, 0.9, 1.4, 0, 0.05, 0, true));
  things.push(scene.floor("surface"));
  // Each throw goes the other way, so the bodies stay near the middle however often they are thrown.
  let way: number = 1;
  if (state.throws % 2 === 1) {
    way = -1;
  }
  let colours: string[] = ["accent", "warning", "#22c55e"];
  let i: number = 0;
  while (i < 3) {
    let id: string = bodyId(state.round, i);
    let x: number = (i - 1) * 0.3;
    let body: scene.Thing = scene.box(id, x, 0.05, 0, 0.1, 0.1, 0.1, colours[i]);
    if (i === 1) {
      body = scene.cylinder(id, x, 0.06, 0, 0.05, 0.12, colours[i]);
    } else if (i === 2) {
      body = scene.sphere(id, x, 0.05, 0, 0.05, colours[i]);
    }
    if (state.picked === id) {
      body = scene.mark(body, "accent");
    }
    things.push(scene.kick(scene.loose(body, 1), state.throws, 0.3 * way, 2, 0.2 * way, 1));
    i = i + 1;
  }
  return things;
}

function onThrow(state: AppState, value: number): AppState {
  return {throws: state.throws + 1, read: state.read, round: state.round, moved: state.moved, picked: state.picked};
}

function onReset(state: AppState, value: number): AppState {
  return {throws: state.throws, read: state.throws, round: state.round + 1, moved: 0, picked: ""};
}

function onWorld(state: AppState, e: scene.Event): AppState {
  if (e.kind === "swipe") {
    return onThrow(state, 0);
  }
  if (e.kind === "tap") {
    return {throws: state.throws, read: state.read, round: state.round, moved: state.moved, picked: e.body};
  }
  if (e.kind !== "settled") {
    return state;
  }
  // For a body that is not a die, e.values says 1 when it was knocked from where it was built.
  let moved: number = 0;
  for (let v: number of e.values) {
    moved = moved + v;
  }
  return {throws: state.throws, read: state.throws, round: state.round, moved: moved, picked: state.picked};
}

function view(state: AppState): ui.View {
  let result: string = "Throw them, or tap one";
  if (state.throws > state.read) {
    result = "In the air...";
  } else if (state.throws > 0) {
    result = ui.numberToString(state.moved) + " of 3 moved";
  }
  let picked: string = pickedName(state);
  if (picked !== "") {
    // Say what was picked, not its id.
    result = result + " - " + picked + " picked";
  }
  return ui.AppTheme("clean", "", [
    ui.Column("default", [
      ui.Header("default", "Bodies", "", "Flick one or press Throw", ""),
      ui.World("fill", 0, "build", "onWorld"),
      ui.Text("body", result),
      ui.ActionBar("spread", [
        ui.Button("primary", "Throw", "onThrow", 0, true),
        ui.Button("secondary", "Reset", "onReset", 0, state.round >= 0)
      ])
    ])
  ]);
}
--- END EXAMPLE ---

A second example, of things that travel: one walking a route, one roaming, one the person steers, places on the ground.

--- TRAVEL EXAMPLE ---
// Things that travel, with no game in them: the second example the world guide carries (vera-world-skill.txt).
//
// A body of parts, built facing +x, walks a closed route by itself (scene.path), its legs swinging two and two
// (scene.swing, phases 0 and 180); a smaller one roams round where it is put (scene.wander). The person steers a third
// with the stick the host draws (scene.player), and its button (here "Jump") throws it up through its kick trigger. Two
// circles on the ground (scene.zone) tell the program when a body comes into one ("enter"). Faster changes only the
// speed: the walker goes on from where it is. The program never keeps a position: the host moves everything.

@jsonable
class AppState {
  jumps: number;
  pace: number;
  round: number;
  entered: number;
  last: string;
}

function init(): AppState {
  return {jumps: 0, pace: 1, round: 0, entered: 0, last: ""};
}

function walker(id: string, colour: string): scene.Thing {
  let parts: scene.Thing[] = [];
  parts.push(scene.box("body", 0, 0.55, 0, 0.8, 0.3, 0.3, colour));
  parts.push(scene.box("head", 0.5, 0.75, 0, 0.25, 0.2, 0.2, colour));
  parts.push(scene.swing(scene.box("leg1", 0.3, 0.2, 0.1, 0.08, 0.4, 0.08, "ink"), 25, 0.7, 0));
  parts.push(scene.swing(scene.box("leg2", 0.3, 0.2, -0.1, 0.08, 0.4, 0.08, "ink"), 25, 0.7, 180));
  parts.push(scene.swing(scene.box("leg3", -0.3, 0.2, 0.1, 0.08, 0.4, 0.08, "ink"), 25, 0.7, 180));
  parts.push(scene.swing(scene.box("leg4", -0.3, 0.2, -0.1, 0.08, 0.4, 0.08, "ink"), 25, 0.7, 0));
  return scene.group(id, 0, 0, 0, parts);
}

// What every id in this round starts with: build makes the ids with it, and the names below match them exactly.
function prefix(state: AppState): string {
  return "r" + ui.numberToString(state.round) + "-";
}

// Say who and where in words, by the exact ids build makes, not read out of the ids.
function whoCame(state: AppState, id: string): string {
  let r: string = prefix(state);
  if (id === r + "walker") {
    return "the walker";
  }
  if (id === r + "roamer") {
    return "the ball";
  }
  if (id === r + "me") {
    return "you";
  }
  return "something";
}

function whereCame(state: AppState, id: string): string {
  let r: string = prefix(state);
  if (id === r + "gate") {
    return "the gate";
  }
  if (id === r + "spring") {
    return "the spring";
  }
  return "a circle";
}

function build(state: AppState): scene.Thing[] {
  let r: string = prefix(state);
  let things: scene.Thing[] = [];
  things.push(scene.sky("#9fd0f0", 0));
  things.push(scene.floor("#6aa84f"));
  // A route round the middle, its corners clear of the post; the walker's y is half its height (its feet on the ground).
  things.push(scene.path(walker(r + "walker", "#8b5a2b"), [-4, -4, 4, -4, 4, 4, -4, 4], 1.2 * state.pace, true));
  things.push(scene.wander(scene.sphere(r + "roamer", 6, 0.25, -6, 0.25, "white"), 2, 0.5 * state.pace));
  things.push(scene.box(r + "post", 0, 0.75, 0, 0.3, 1.5, 0.3, "#5b4636"));
  // The person's: it starts on the ground, clear of the rest; its kick trigger is the count of jumps.
  let me: scene.Thing = scene.kick(scene.box(r + "me", -2, 0.3, 2, 0.5, 0.6, 0.4, "accent"), state.jumps, 0, 4, 0, 0);
  things.push(scene.player(me, 3, "Jump"));
  things.push(scene.zone(r + "gate", 4, 0, 1.2, "accent"));
  things.push(scene.zone(r + "spring", -6, -6, 1.2, "warning"));
  return things;
}

function onWorld(state: AppState, e: scene.Event): AppState {
  if (e.kind === "action") {
    return {jumps: state.jumps + 1, pace: state.pace, round: state.round, entered: state.entered, last: state.last};
  }
  if (e.kind === "enter") {
    return {jumps: state.jumps, pace: state.pace, round: state.round, entered: state.entered + 1, last: whoCame(state, e.body) + " at " + whereCame(state, e.other)};
  }
  return state;
}

function onFaster(state: AppState, value: number): AppState {
  let pace: number = state.pace * 1.5;
  if (pace > 3) {
    pace = 1;
  }
  return {jumps: state.jumps, pace: pace, round: state.round, entered: state.entered, last: state.last};
}

function onReset(state: AppState, value: number): AppState {
  return {jumps: 0, pace: 1, round: state.round + 1, entered: 0, last: ""};
}

function view(state: AppState): ui.View {
  let result: string = "Steer with the stick";
  if (state.last !== "") {
    result = ui.numberToString(state.entered) + " came in - last " + state.last;
  }
  return ui.AppTheme("clean", "", [
    ui.Column("default", [
      ui.Header("default", "Field", "", "Steer with the stick, jump with the button", ""),
      ui.World("fill", 0, "build", "onWorld"),
      ui.Text("body", result),
      ui.ActionBar("spread", [
        ui.Button("primary", "Faster", "onFaster", 0, true),
        ui.Button("secondary", "Reset", "onReset", 0, state.round >= 0)
      ])
    ])
  ]);
}
